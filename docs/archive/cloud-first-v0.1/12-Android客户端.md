# Android 客户端

> 历史方案：云端 Agent 架构，已于 2026-11-22 被边缘 Agent 架构替代。仅作历史参考，当前设计见 [产品文档](../../product/README.md)。
## 1. 默认技术方向

以原生 Android 外壳承载聊天、任务、设备、记忆和语音，优先复用 OpenClaw 官方节点能力。默认 Kotlin / Compose 配合 WebView 形象层，协议和表现映射可与 Mac 共用，系统操作与生命周期保持原生实现。

是否直接维护官方客户端的产品分支，或抽取其节点代码到独立外壳，在构建原型后决定。无论哪种方式，V1 用户只看到一个清晰的产品入口。

## 2. 主要页面

聊天首页提供形象区域、字幕、输入和语音按钮；任务页按等待 / 执行 / 待处理分组；记忆页可以切换全局和各设备；设备页展示 Mac 与手机的实际能力；设置管理声音、通知、主动联系和本地权限。

任务卡片始终展示执行设备，不能让用户误以为在手机发出的任务一定在手机执行。

## 3. 前后台与服务

Android 的后台启动和麦克风前台服务有明确限制。产品只承诺在系统允许、权限有效且用户开启的模式中工作；不能依靠一条推送就保证在任意后台状态打开麦克风或执行 GUI。[后台服务限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)、[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)

区分三种运行模式：

- 前台互动：聊天、语音、形象和可用的手机操作。
- 用户开启的伴随连接：使用适当的前台服务与可见状态；具体能力按系统条件声明。
- 普通后台：依赖适配的通知和恢复任务，不承诺持续媒体 / GUI 能力。

进入后台后根据真实状态更新 readiness。后台被系统终止时，云端任务保留为等待设备或待对账，而不是显示手机还在工作。

## 4. 权限与能力

麦克风、通知、联系人、日历、照片、位置和手机操作能力分别申请。只启用用户实际需要的能力；未授予时仍能正常文字聊天。

通知读取和跨应用操作是不同能力。读到通知不代表允许代用户点击所有按钮或发消息。锁屏、受保护窗口和验证码等情况明确返回前台 / 用户介入要求。

## 5. 手机操作扩展

先提供已验证的系统命令，再增加场景化 GUI 适配器。原型评估 Accessibility 或受控调试方案时，分别测连接恢复、目标识别、锁屏行为和耗电，不能把开发机成功一次当成普适支持。

GUI 控制期间使用本地资源锁，避免用户操作和自动输入互相覆盖。用户接管时停止新输入，重新观察后才允许明确续跑。

## 6. 声音、形象与通知

支持按住说话和可打断对话；后台收不到合法麦克风能力时停止采集并更新 UI。未取得声音焦点不播放云端语音片段。

形象默认在应用内运行，后台停止渲染。悬浮窗是单独可选功能，不作为使用助理的必要条件。锁屏通知默认使用简短预览，不直接展示完整私人记忆。

推送适配需要考虑实际机型和网络环境，第一版抽象为 notification provider，不假设所有 Android 都能稳定使用同一个通道。通知唤起后通过 API 读取最新状态，不信任推送载荷就是最终任务结果。

## 7. 本地持久化与恢复

设备私钥存系统安全设施，缓存与步骤回执分开。系统杀进程后，重启先上传未同步回执、核对当前绑定和任务，再恢复聊天事件订阅。

网络在 Wi-Fi / 蜂窝间切换时请求 ID 不变。音频连接重新建立可用新 session，但已经提交的转写消息和工具任务不得重复创建。

## 8. 测试矩阵

至少覆盖一台目标实际手机、不同 Android 版本的模拟环境、前后台切换、锁屏、系统杀进程、节电模式、网络变化、权限撤销、升级和重装。各机型支持边界记录在能力清单，不在用户界面声称未验证的通用兼容性。
