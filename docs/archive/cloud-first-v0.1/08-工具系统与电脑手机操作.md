# 工具系统与电脑、手机操作

> 历史方案：云端 Agent 架构，已于 2026-11-22 被边缘 Agent 架构替代。仅作历史参考，当前设计见 [产品文档](../../product/README.md)。
## 1. 工具契约

工具表达能力，执行器完成动作，任务账本记录副作用。工具注册项包含：工具 ID / 版本、输入输出 schema、支持平台、只读或写操作、所需能力、授权边界、超时、可取消性、幂等策略和结果核验方式。

模型看到的是工具语义，不是设备管理密钥。写操作工具必须先形成任务步骤再执行。只读能力可以直连，但仍需通过当前设备和工具策略检查。

## 2. 首版工具清单

| 类别 | 例子 | 默认执行策略 |
| --- | --- | --- |
| 记忆 | 查询、保存、更正、删除事实 | 走记忆服务，带版本和来源 |
| 任务 | 提交、查询、取消、补参数 | 走任务账本，不直接操作设备 |
| 设备发现 | 设备、能力、就绪状态 | 只读；不把设备名称当身份 |
| 文件 | 列表、读取、分类、移动 | 明确根目录；写入分步骤、核对文件标识 |
| 桌面 | 截图、观察、点击、输入 | 绑定目标和观察版本；GUI 串行执行 |
| 手机系统 | 查询日历、读通知、添加日程 | 以设备实际授权和原生命令为准 |
| 手机 GUI | 观察、定位元素、输入、提交 | 独立适配器；逐个场景验收后开放 |
| 外部服务 | 未来邮件、日历、知识库连接 | 独立连接与操作授权，不作为首版依赖 |

## 3. Mac 执行路径

优先结构化 API、文件操作和应用明确接口，再使用桌面视觉操作。沿用 OpenClaw 配对节点和其支持的 computer provider，避免重新实现整套截图与输入协议。

原生 computer 工具支持不代表全部调用已具备本产品的持久步骤回执。第一版写操作需要包装器或设备扩展，确保动作前写本地日志、动作后可查结果。没有完成这层验证的能力只能标成实验能力，不计入可靠任务验收。

应用操作基本循环为：观察 → 选择目标 → 生成单步意图 → 保存步骤 → 校验观察是否仍适用 → 执行 → 观察后置条件 → 提交回执。窗口切换、缩放或设备恢复后重新观察，不继续使用旧坐标。

文件移动步骤保存源、目标、预期文件身份和冲突策略。目标已有同名文件时按已选规则处理；没有规则则暂停，不无声覆盖。

## 4. Android 执行路径

第一层复用官方节点已提供的系统能力，第二层实现独立的 App 操作适配器。后者可以评估原生 Accessibility 或受控调试连接，但不把它当成官方节点已经提供的完整能力。

单个 GUI 工具输出应包含：观察 ID、应用 / 页面标识、可用动作、元素引用、需要前台 / 解锁的条件和拒绝原因。写操作遵循同一任务步骤与本地回执协议。

解锁、验证码、受保护窗口、系统限制可能需要用户处理。遇到这些状态，任务进入明确等待状态，不循环尝试点击，也不把截图为空解读成设备没有内容。

## 5. 执行器抽象

每个平台实现四类能力：

- `describeCapabilities()`：声明支持和当前就绪状态。
- `executeStep(command)`：校验当前授权、幂等键和资源锁，再执行。
- `getReceipt(stepId)`：恢复时查询已接受 / 已完成结果。
- `cancelStep(stepId)`：尽力停止可取消工作，并返回真实状态。

这些是本产品的逻辑接口，不是 OpenClaw 已有同名方法。与 node.invoke 的映射、原生 app 的回执扩展需要在集成阶段验证。

## 6. 调用输入与结果

命令至少携带 task、step、plan revision、目标绑定、操作 hash、幂等键、fencing token、deadline 和当前授权引用。设备先校验目标与本地绑定一致，再写 accepted。

结果区分 `succeeded`、`failed_no_effect`、`failed_with_known_effect`、`unknown` 和 `rejected`。同时返回实际效果、后置条件、错误、已生成附件和观察引用。服务端归一为步骤状态，不能仅根据 HTTP 200 判断成功。

截图和文件结果通过受控附件引用传输，不在事件中塞入无限 base64。敏感内容是否上传由所选能力和任务决定，诊断日志不默认记录完整屏幕或文件正文。

## 7. 工具权限和绕过问题

产品可靠写工具接管某类操作后，agent 的普通工具面不能再直接暴露同类绕过入口。必要时通过工具 allowlist、策略钩子或有限核心修改强制路由。否则即使任务账本完善，模型仍可能在账本外完成另一次操作。

第一版不默认给模型任意 shell。确需开发类终端能力时，为特定设备、工作区和任务建立独立配置；不能把普通文件整理任务扩大为主机管理权限。

## 8. 验收

工具 schema 校验、版本不兼容、目标误配、旧观察拒绝、重复命令、资源竞争、权限撤销、动作后崩溃和未知结果核验均需覆盖。首个可靠执行垂直场景选“指定目录内文件整理”，然后再扩展 GUI 写操作。
