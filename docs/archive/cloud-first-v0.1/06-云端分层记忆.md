# 云端分层记忆

> 历史方案：云端 Agent 架构，已于 2026-11-22 被边缘 Agent 架构替代。仅作历史参考，当前设计见 [产品文档](../../product/README.md)。
## 1. 职责与边界

记忆模块保存经过整理、可以追溯与更正的信息。原始聊天仍由会话系统保存，任务步骤和回执仍由任务账本保存。检索索引、设备摘要、会话摘要都是派生结果，不能覆盖事实的权威版本。

设备记忆同样位于云端。终端只缓存需要展示或执行的最小片段，并标记版本与有效期。

## 2. 记忆结构

| 类别 | 内容 | 作用域与时效 |
| --- | --- | --- |
| 全局事实 | 偏好、长期目标、关系、稳定背景 | `global`；定期复核或由用户更正 |
| 设备事实 | 目录、应用环境、操作习惯 | `device + logical_device_id`；绑定变化时重新核对环境事实 |
| 情节记忆 | 重要交流或事件摘要 | 可以 global 或 device；保留事件时间和来源 |
| 程序记忆 | 已验证的做事方法与约束 | 版本化；与可执行 skill 分开审批发布 |
| 临时状态 | 设备是否解锁、应用当前页面 | 短 TTL；主要由设备状态服务持有，不能长期当真 |
| 设备目录 | 摘要、能力引用和详情引用 | 派生数据；带所依据事实的 revision |

授权凭据、系统私钥不保存为普通可检索记忆。用户在聊天里出现的敏感值应由专门配置入口处理，不进入自动事实抽取。

## 3. 三种设备关系

- `source_device_id`：信息从哪台设备产生。
- `applicable_device_id`：事实适用于哪台设备；global 时为空。
- `target_device_id`：任务准备在哪台设备执行，属于任务记录。

例如在 Android 上说“Mac 的论文目录是某路径”，来源是 Android，事实作用域是 Mac。检索“Mac 论文目录”不能因为发起端是手机就选择 Android 的目录。

## 4. 核心对象

`memory_item` 有稳定 ID、主人、助理、类型、作用域、适用设备、当前 revision 和状态。每次修改创建不可变 `memory_revision`，保存正文、结构化值、有效时间、来源引用和修改原因。

来源至少包含消息 ID / 设备结果 ID、事件时间、采集时间和证据类型。模型推断保留为候选，不因文字自信就升级为用户确认事实。

状态统一为 `candidate`、`active`、`disputed`、`superseded`、`deleted`。当前可召回版本须为 active，且符合有效时间与调用权限；旧版本仅用于授权的历史查看。

## 5. 写入流水线

1. **提出候选**：显式“记住”同步走保存流程；普通对话异步提取候选。
2. **确定范围**：参考明确设备语义和受信来源；无法判断时保留候选或简短澄清。
3. **去重与冲突检查**：先匹配实体 / 字段，再用语义近似辅助，不能仅凭向量相似直接覆盖。
4. **校验证据**：用户明确陈述、设备观测、模型推断分开标记。
5. **事务提交**：修订、当前指针、索引待更新事件在同一事务写入。
6. **派生更新**：worker 更新检索向量、全文索引和设备目录。
7. **失效通知**：发布新 revision，刷新客户端与语音上下文。

重复候选按来源事件和提取器版本去重。提取器重跑可以产生新分析，但不能无条件制造另一份相同事实。

## 6. 全局设备索引

设备目录存：逻辑设备、用途摘要、能力引用、若干高价值事实引用、source revision、水位和更新时间。索引指向事实 ID 与版本，不复制完整历史。

首版优先同库事务记录“目录需要刷新”；后台用 outbox 构建摘要。查询时目录落后则回查当前事实。不能让“索引已返回结果”绕过对事实 active 状态和权限的二次检查。

设备移除后可保留历史记忆，但目录标注设备不可执行。重新绑定会触发环境事实复核，不能默认旧软件、路径和权限仍有效。

## 7. 召回流程

1. 校验 owner、assistant、host audience 和当前会话权威。
2. 分析查询涉及的实体与设备，建立允许范围。
3. 读取结构化关键事实与相关设备目录。
4. 在允许范围内做全文 / 向量检索。
5. 回读当前 active revision，去除旧版本、删除项和不可见结果。
6. 按相关性、来源可靠程度、时间与重复度排序，裁剪到上下文预算。
7. 返回正文、引用、revision 和覆盖信息，组装本轮快照。

所有设备属于同一主人时，设备 scope 主要表达适用性；仍不能把其他 owner 或受限 conversation 的内容带入。scope 选择不能由模型传入一个任意 owner 字符串来决定。

## 8. 更正、并发与冲突

修改带 `expected_revision`。当前版本不匹配则返回 `REVISION_CONFLICT`，客户端或 agent 重新读取，再提出合并或明确覆盖。不得静默采用最后写入者。

用户明确更正可以将旧版标为 superseded。两个相互矛盾、又没有决定性证据的陈述标为 disputed，不合成一个看似确定的事实。涉及路径和执行规则时，冲突会阻止相关写操作任务继续派发。

运行开始捕获记忆快照；执行副作用前重读关键依赖。若计划依赖值变化，重新规划并生成新步骤，不能复用旧步骤幂等键去执行新操作。

## 9. 删除与遗忘

删除事务先标记 deleted 并产生墓碑事件，在线查询立即按当前状态过滤；向量清理、摘要重建与缓存失效随后完成。活动语音 session 收到失效后，下一轮重建上下文；无法证明已刷新时，不继续使用旧记忆快照。

删除长期事实、删除原聊天、删除附件、备份到期是不同动作。记忆中心明确说明范围，支持一并发起关联数据清理，但不能承诺外部模型已“忘掉”。恢复备份时先应用恢复点之后的删除墓碑，避免旧事实重新出现。

## 10. 检索降级

向量服务失败时使用结构化读取和全文检索；摘要缺失时读取原事实；全部相关检索失败时说明覆盖不足。模型不能把“没有检索到”改写成“这件事从未发生”。

## 11. 验收

跨设备新会话召回、适用设备选择、并发更正、源消息去重、过期临时状态、删除后索引滞后、备份恢复墓碑、设备重装和受限会话可见性均必须通过。数据实体见 [数据模型](14-数据模型与存储.md)，一致性场景见 [故障处理](21-一致性与故障处理.md)。
