# OpenClaw 集成与改造

> 历史方案：云端 Agent 架构，已于 2026-11-22 被边缘 Agent 架构替代。仅作历史参考，当前设计见 [产品文档](../../product/README.md)。
## 1. 基线与原则

研究基线为 `openclaw/openclaw@423ae09072039a3bb42ed695cc47a366ee8e1fd5`。这是固定源码证据，不等于建议直接把 main 快照上线。部署前选定可构建、可回退的版本，记录与研究基线的能力差异。

优先保留官方 Gateway、会话、模型和节点协议。新增产品逻辑集中在插件与适配层；确有必要的核心 / 原生客户端修改单独记录，不能承诺完全零 fork。

## 2. 复用与新增

| 部分 | 做法 | 需要证明的边界 |
| --- | --- | --- |
| Gateway、agent 循环和会话 | 复用 | 自有 request 能关联和查询真实 run |
| DeepSeek provider | 复用官方支持路径 | 当前版本模型、工具多轮、流式与视觉能力 |
| 配对与节点调用 | 复用 | 产品逻辑设备与节点绑定、撤销同时生效 |
| Mac computer 能力 | 复用 provider / 节点 | 权限和当前观察；写操作进入任务账本 |
| Android 系统命令 | 复用可用能力 | 实机可用范围；副作用回执可恢复 |
| 记忆 provider / hooks | 新增产品插件 | scope、设备上下文、修订与删除 |
| Workboard | 可复用为投影 | 不能作为设备动作成功的唯一证据 |
| 通用设备步骤恢复 | 新增账本与设备回执 | 不是直接依赖 node pending 队列 |
| 虚拟形象、产品 UI | 改造客户端 | 原生生命周期、Web 渲染和共享事件 |

## 3. 插件划分

### `companion-bridge`

负责产品身份验证、conversation / session 映射、请求去重、提交与查询运行、响应事件归一。拟定义 `companion.turn.submit` 和 `companion.turn.lookup` 这类内部扩展命令；这些名称是产品设计，不是官方已有方法。

只有受信服务可提交带产品身份的内部调用。Gateway 的现有设备验签上下文与产品 API 的转发上下文保持来源标签，不混为一谈。插件不接受公网任意字符串伪造 owner 或来源设备。

### `companion-memory`

提供层级记忆服务适配、上下文补充、标准 memory provider 和明确的设备记忆工具。作为活动 memory slot 时，标准 search / get / store 的范围要固定，并尊重宿主 audience；设备过滤、更正与删除使用自有契约。

只保留一个长期事实写入权威。不能同时开启两套自动事实写入并期待它们自行一致。需要保留原会话检索时，通过已支持的后端适配方式验证复用，不直接假设可以同时选择两个活动 memory slot。

### `companion-tasks`

提供任务工具、步骤状态、Workboard 投影、调度与恢复。调度 worker 只能通过受支持、具备当前授权的运行路径调用节点；不能拿到一个全权 Gateway 凭据后绕过正常工具政策。

SDK 节点运行时是否对所选插件模式开放、后台如何建立授权运行，必须原型验证。若需要可信内建插件或小核心扩展，写成明确修改项，避免伪装成普通外部插件即插即用。

## 4. 钩子与上下文

- `before_prompt_build`：注入有预算的相关事实与设备目录，不替换整套系统规则。
- `agent_end`：基于已记录的完成轮次提出记忆候选，不用它直接宣布设备任务成功。
- 工具策略 / 调用钩子：限制绕过任务账本的写入口，记录关联信息；实际支持哪些阶段以选定版本验证。
- 服务启动 / 停止：启动恢复扫描、退役 worker、停止新认领并等待可收尾工作。

源码中的 hook context 已有 `requesterDeviceId`；工具工厂上下文有 run ID，但未直接携带该字段。非 user 触发的身份投影还会隐藏当前 requesterDeviceId。不能简单用“当前 session 的最后设备”来补齐。

优先用宿主支持的受信绑定贯通来源；若使用 run 关联缓存，必须证明建立时序、并发隔离和清理不会产生错误权威。无法证明时，加窄范围、带测试的上下文字段补丁。

## 5. 设备端改造

Mac 与 Android 均需本地步骤日志、回执查询、取消与资源锁。现有节点命令能否直接包装须逐类验证；对于原生 app 不支持的扩展点，需要修改原生代码，而不只是写服务端插件。

UI 增加产品会话、任务、记忆与形象面板。节点连接保持其原生受限凭据，聊天侧连接产品 API。两条连接在本地共用经过验证的逻辑设备映射，不能由形象 WebView 随意指定。

## 6. 必做原型

| 编号 | 原型 | 通过标准 |
| --- | --- | --- |
| S01 | 自有 API → Gateway 请求关联 | 断线重试不会创建第二个运行，未知情况可查询 |
| S02 | 受信来源贯通 memory / tool | 多端并发不串，后台来源不被误当授权 |
| S03 | Mac 本地回执垂直场景 | 动作前记录，重启后可查，成功回执丢失不重复 |
| S04 | Android 能力与回执 | 实机测出前后台边界，命令结果可对账 |
| S05 | 活动 memory slot 与管理 API | 搜索范围、修订、删除和失效一致 |
| S06 | 写操作统一路由 | agent 不能绕过步骤账本执行同类副作用 |
| S07 | 客户端构建与形象层 | 原生节点正常，渲染不破坏权限与生命周期 |

S01 / S02 / S03 是投入完整产品 UI 前的阻断验证。失败时先缩小能力范围或调整接缝；结构性代价过大再评估 DeepAgents + LangGraph，记忆与任务协议尽量不变。

## 7. 版本与维护

固定 Gateway、插件、协议、客户端和模型 provider 版本，维护兼容矩阵。核心补丁独立于产品 UI 修改，每个补丁记录原因、官方替代点和回归用例。升级先跑协议与恢复测试，再切换真实设备。

研究快照要求的 Node 引擎不是当前本机 Node 22，后续构建需单独配置受支持环境；本轮未修改环境。源码与官方参考见 [证据文档](20-参考资料与证据.md)。
