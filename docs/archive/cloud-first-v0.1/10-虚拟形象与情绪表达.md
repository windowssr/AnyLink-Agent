# 虚拟形象与情绪表达

> 历史方案：云端 Agent 架构，已于 2026-11-22 被边缘 Agent 架构替代。仅作历史参考，当前设计见 [产品文档](../../product/README.md)。
## 1. 职责

形象层负责把统一助理的交流状态呈现出来，不独立调用另一套聊天模型，也不保存另一套人格和长期记忆。客户端渲染，服务器发送有边界的表现指令。

首版默认采用可替换渲染接口。原型优先验证 VRM Web 渲染；若资产、性能或封装不合适，可先用基本 2D 状态动画完成闭环。Live2D 是另一种适配器选择，不能把第三方 SDK 与模型资产的许可一概当成 OpenClaw 的 MIT。

## 2. 表现状态

| 状态 | 表现 | 触发来源 |
| --- | --- | --- |
| `idle` | 呼吸、眨眼、轻微注视 | 无活动且资源允许 |
| `listening` | 面向用户、倾听动作 | 麦克风真实采集中 |
| `thinking` | 简短思考动作 | 本轮正在生成或等待明确结果 |
| `speaking` | 口型与适度动作 | 实际播放器正在播放对应音频 |
| `working` | 简洁任务提示 | 当前有相关任务；不暗示持续注视屏幕 |
| `attention` | 提醒动作 | 策略允许的通知或待处理事项 |
| `offline` | 收敛表现与连接标记 | 无法连接服务端 |

状态优先级为用户手动停止 / 系统不可用优先，其次倾听与说话，再次提醒和空闲。后台和节能模式减少帧率或停止渲染。

## 3. 情绪协议

服务器只发送有限标签，例如 neutral、warm、focused、happy、concerned，以及受限强度和持续时间。标签可以由模型提出，但经过规则校验；客户端映射到可用表情和动作。

表现标签不是对用户情绪的医学或心理判断，也不构成事实。产品不使用“你不理我我就难受”等话术制造回应压力。角色风格可以有幽默和亲近感，但必须尊重用户设置的互动节奏。

## 4. 口型和动作同步

音频提供 viseme / 音素时间标记时按标记驱动；没有标记时由本地音量包络做近似张口。后者标成近似实现，不承诺逐音素同步。

播放开始才进入 speaking。打断、静音或切换声音焦点立即停止旧 generation 的嘴部动作；迟到的音频和动作事件不得重新触发。

动作由白名单 motion ID 选择，带 response ID、generation、起始时间和时长。禁止服务端返回任意 JavaScript 或任意原生调用来控制角色。

## 5. 资产包

资产包 manifest 包含版本、渲染类型、文件 hash、模型入口、表情 / 动作映射、性能档位、署名和许可来源。资产下载校验后本地缓存，切换失败保留上一个可用形象。

相同 assistant 的形象设置跨设备共享，性能档位可以按设备不同。Android 可使用低精度材质、较低帧率和更少物理模拟，不要求与 Mac 每帧一致。

第三方模型不随意打包分发；正式选定资产时核对使用与分发条件。渲染库的开源许可与角色模型授权分别记录。

## 6. 原生桥边界

共享 Web 形象层只接收表现事件，并能发起有限 UI 意图，例如打开聊天、开始语音和关闭形象。不能直接拿到设备私钥、文件系统、任意 URL 执行或 shell。

Mac 可以有透明伴随窗口，Android 默认在应用内呈现。跨应用悬浮形象属于可选能力，需要单独系统设置和耗电验证，不作为正常使用前提。

## 7. 性能目标

初始目标为活跃时 30 FPS，后台停止渲染；低性能 Android 可降到 15 FPS。目标需以真实资产和设备测量，不使用空场景帧率作为产品结论。

渲染失败时聊天、任务和语音仍可使用。形象不能阻塞消息发送和设备执行。

## 8. 验收

覆盖无资产、资产损坏、WebView 崩溃、离线、字体缩放、打断、静音、声音焦点切换、屏幕休眠和后台。验收同时记录内存、CPU / GPU、功耗与帧率。

渲染适配器参考 [three-vrm 官方仓库](https://github.com/pixiv/three-vrm)；Live2D Core 的边界参考 [官方说明](https://docs.live2d.com/en/cubism-sdk-manual/cubism-core/)。这些来源支持技术评估，不代表已完成本产品的集成和资产选择。
