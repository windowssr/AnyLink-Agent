## 1. 研究范围

本方案基于先前对四个开源项目的官方文档与固定源码取样审计。67 个公开文件完成下载内容的 Git blob SHA 与 SHA-256 复核。队列模块做过 5 项隔离行为探针，但没有安装运行完整框架、连接真实设备或调用付费模型。

因此，源码契约与静态实现可以支持选型和识别缺口，不能替代本产品的真实集成、恢复和延迟测试。本文中的模块拆分、表结构、API、状态和目标数字都是新的设计决定。

## 3. OpenClaw 证据索引

### 运行拓扑和设备

- [官方远程 Gateway 与节点命令流](https://docs.openclaw.ai/gateway/remote)：支持把 Gateway 与状态集中运行，设备作为客户端 / 节点。
- [Android 节点](https://docs.openclaw.ai/platforms/android)：说明原生客户端、手机命令、Talk 和运行条件。
- [Computer use](https://docs.openclaw.ai/nodes/computer-use)：说明桌面 provider、节点能力与系统要求。
- [DeepSeek provider](https://docs.openclaw.ai/providers/deepseek)：模型和工具集成以选定 provider 版本为准。

### 记忆与受信身份

- [记忆请求与 audience 类型](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/plugins/memory-provider-types.ts)：标准请求没有直接的设备作用域字段。
- [provider handle](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/plugins/memory-provider-runtime-types.ts)：标准能力与业务更正 / 删除需求需要适配。
- [hook context 的设备字段](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/plugins/hook-agent-context.types.ts#L89)：直接来源契约。
- [实际身份投影](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/plugins/hook-agent-context.ts#L128)：非 user 触发与后台 ancestry 的区别。
- [工具工厂上下文](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/plugins/tool-types.ts#L57)：有 run 关联，但不能据此假设所有来源字段已贯通。
- [memory slot 注册](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/plugins/plugin-api.types.ts#L459)：活动 slot 的选择。
- [跨 agent 记忆边界](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/docs/concepts/multi-agent.md#L260)：不能通过复制设备人格自动获得统一记忆。
- [内建记忆存储](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/docs/concepts/memory-builtin.md)：集中存储与设备语义是不同问题。

### 任务与恢复

- [协议说明](https://docs.openclaw.ai/gateway/protocol/rpc-devices-nodes-and-approvals)：节点调用与 pending API 描述。
- [node-pending-work 实现](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/gateway/node-pending-work.ts)：类型限定、进程 Map 和 drain 消费行为。
- [另一类 pending action](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/gateway/node-runtime-state.ts)：也是进程状态，不能当通用持久设备任务。
- [iOS 前台受限判定](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/gateway/server-methods/nodes.invoke-foreground.ts)：特定延期路径的适用范围。
- [延期的运行授权限制](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/src/gateway/server-methods/nodes.invoke.ts#L503)：不能保存一次运行的临时权威供后续任意调用。
- [Workboard 生命周期与恢复](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/docs/plugins/workboard.md#L724)：可复用的任务板与会话对账。
- [插件 scheduler 边界](https://github.com/openclaw/openclaw/blob/423ae09072039a3bb42ed695cc47a366ee8e1fd5/docs/plugins/sdk-runtime/gateway-and-nodes.md#L59)：进程生命周期调度不能代替持久任务账本。

文档中的 durable 描述与本次固定队列源码存在差异，这是需要验证的集成风险；不据此断言 OpenClaw 所有队列和状态都不持久。

## 4. 替代框架

- [DeepAgents StoreBackend](https://github.com/langchain-ai/deepagents/blob/65d33b2c114d0edd34ed48235e8be6654e691739/libs/deepagents/deepagents/backends/store.py#L111) 和 [CompositeBackend](https://github.com/langchain-ai/deepagents/blob/65d33b2c114d0edd34ed48235e8be6654e691739/libs/deepagents/deepagents/backends/composite.py#L198)：适合自定义存储命名空间与路由。
- [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：区分会话 checkpoint 与跨会话 store，实际恢复仍需使用持久实现。
- [Letta 部署](https://docs.letta.com/agent-sdk/deployment) 和 [SDK 共享仓库](https://docs.letta.com/agent-sdk/repositories)：自管运行时与 Cloud 共享功能边界不同。
- [Hermes 桌面远程执行位置](https://github.com/NousResearch/hermes-agent/blob/52b527194b364ba073c85f0b1cd8c63bc9264cac/apps/desktop/README.md#L164)：桌面远程模式不等于自动获得本机执行。
