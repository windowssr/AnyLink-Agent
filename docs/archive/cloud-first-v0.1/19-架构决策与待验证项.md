# 架构决策与待验证项

> 历史方案：云端 Agent 架构，已于 2026-11-22 被边缘 Agent 架构替代。仅作历史参考，当前设计见 [产品文档](../../product/README.md)。
## 1. 状态说明

本文“采用”表示设计默认；“待验证”表示尚无本产品集成证据；“可替代”表示保留接口但不立即实施。没有把用户未表达的资产风格、预算或服务器条件写成既定偏好。

## 2. 架构决策

### ADR-01：OpenClaw 作为第一底座

采用。理由是已有 Gateway、多设备节点、会话和工具协议，符合尽快改造成熟项目的目标。代价是插件版本兼容、节点回执扩展和原生客户端维护。

替代方案为 DeepAgents + LangGraph；当可信上下文、可靠执行接缝或维护成本无法接受时重新评估，不因为已经写了 UI 而被底座锁死。

### ADR-02：云端是人格、记忆与任务的权威

采用。终端不独立调用长期聊天模型、不维护另一套人格记忆。允许缓存、离线草稿与本地回执。代价是核心对话依赖服务器，离线时主要提供查看与等待体验。

### ADR-03：一个主人格，设备作用域由业务记忆服务管理

采用。不按设备复制整个人格。记忆保留来源设备和适用设备，全局目录引用设备详情。设备 scope 主要表达相关性，不冒充多人租户隔离。

### ADR-04：任务账本与聊天运行分开

采用。模型轮次结束不等于任务完成，任务等待设备也不要求挂住一个模型运行。Workboard 可投影展示，但产品账本决定物理设备步骤状态。

### ADR-05：副作用以步骤和回执驱动

采用。设备动作前写本地日志，操作后存结果；未知结果先对账。不能普遍保证外部 App exactly-once。代价是需要设备端修改和更多状态管理。

### ADR-06：模块化服务，暂不拆微服务

采用。产品 API、记忆、任务与通知先共享一个产品数据库和少量进程，保持明确模块边界。优先事务与 outbox，不提前引入复杂消息基础设施。

### ADR-07：同一响应驱动文字、语音与形象

采用。只有一个 response owner，使用 response ID、generation 和播放时间轴。实时语音提供商作为可替换适配器；角色表现不能成为另一套会话大脑。

### ADR-08：第一版不依赖手机无限后台

采用。按实际系统能力暴露 readiness，通知负责唤起，前台语音和可控操作先完成。后台常驻与悬浮形象均需单独验证。

### ADR-09：产品协议与 OpenClaw 协议隔离

采用。客户端依赖 `/v1` 产品契约，适配器吸收上游变动。节点传输保留原生协议；产品设备身份与原生节点身份显式映射。

### ADR-10：默认不长期保存原始音频

采用。优先保留必要转写与任务证据；音频收藏和诊断分别开启。删除事实、历史聊天和备份分别可管理，不做无法兑现的整体遗忘承诺。

## 3. 阻断验证

| 项 | 问题 | 验证方法 | 失败后的选择 |
| --- | --- | --- | --- |
| S01 | 转发请求如何幂等关联 Gateway run | 提交前后断线、重启、查询 correlation | 改提交适配器；保持未知状态，禁止盲重发 |
| S02 | 来源设备如何可信贯通工具与记忆 | 同会话多设备并发、后台续跑、过期上下文 | 增加窄核心字段或受信插件绑定 |
| S03 | Mac 动作是否有可恢复回执 | 选定文件任务逐故障点注入 | 扩设备执行器；不发布未达标写能力 |
| S04 | Android 能力在目标机型上的实际边界 | 前后台 / 锁屏 / 系统终止真机测试 | 缩小到已验证系统命令 |
| S05 | memory slot 与自有业务记忆能否一致 | scope、修订、删除、受限 audience | 标准工具仅保留保守范围，自有接口接管管理 |
| S06 | 能否阻止账本外写操作 | 模型尝试直接调用同类原生工具 | 调整工具面 / 策略；必要时核心补丁 |
| S07 | 原生客户端改造和发布成本 | Mac / Android 构建与最小形象接入 | 先独立产品 UI 配官方节点；V1 再整合 |

S01～S03 是完整产品实现前的关键退出门槛。其他原型决定哪些能力进入 V1，哪些保持实验状态。

## 4. 尚未确定的产品配置

- 服务器位置、域名、资源和备份目标。
- 助理正式名称、形象风格与可分发资产。
- 语音 ASR / TTS / 实时模型提供商与预算。
- Android 目标机型、系统版本和可用通知渠道。
- 默认设备工作区、允许的写操作和主动联系频率。
- 是否需要未来多人、iPhone 或 Windows / Linux。

这些配置不阻止当前设计，实施时通过配置和小范围访谈确定。不会在文档阶段申请 API Key 或替用户订购服务。

## 5. 决策变更流程

实现发现新事实后，更新受影响模块、接口与验收，再在此记录日期、理由和替代方案。保持同一状态机和数据权威，避免一份文档已经改为新方案，另一份仍把旧方案当默认。
