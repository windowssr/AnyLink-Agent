# 用户体验与关键场景

> 历史方案：云端 Agent 架构，已于 2026-11-22 被边缘 Agent 架构替代。仅作历史参考，当前设计见 [产品文档](../../product/README.md)。
## 1. 主要界面

产品由伴随视图、聊天、任务、记忆和设备设置组成。虚拟形象是交流入口，不承担复杂任务管理页面的全部功能。

| 界面 | 主要内容 | 用户可以做什么 |
| --- | --- | --- |
| 伴随视图 | 形象、当前交流状态、简短消息、语音开关 | 唤起聊天、开始说话、停止播放、收起形象 |
| 聊天 | 会话、流式回复、引用、任务卡片 | 文字 / 语音输入、切换设备目标、打开任务详情 |
| 任务中心 | 等设备、运行、待处理和历史任务 | 看步骤、取消、重新授权、处理不确定结果 |
| 记忆中心 | 全局记忆、设备记忆、来源和修订 | 查看、更正、删除、调整适用范围 |
| 设备中心 | 在线与就绪状态、能力、授权、当前任务 | 重命名、绑定逻辑设备、暂停执行、解除配对 |
| 助理设置 | 人格、声音、形象、主动联系偏好 | 更换表现方式、设置免打扰和互动频率 |

客户端不向日常用户展示 token、租约、插件名称或数据库表名；诊断详情放在独立入口。

## 2. 首次使用

用户连接自己的服务器，建立主人身份，配对当前设备，然后配置模型服务。服务端保存凭据，客户端只显示配置是否可用。Mac 的屏幕 / 辅助功能权限和 Android 的通知 / 麦克风等权限，按启用的具体能力引导授予。

之后选择助理名称、称呼、语言、声音与形象。没有形象资产也能完成设置并进入文字聊天，不让装饰性配置阻塞核心闭环。

设备配对成功不等于全部能力可用。设备中心分别显示“已连接”“可以读取文件”“可以操作桌面”“麦克风未启用”等实际状态。

## 3. 场景 A：跨设备延续交流

Android 上讨论研究计划，之后在 Mac 打开同一会话继续，看到统一历史。若在 Mac 新开会话，系统通过长期记忆提取目标与偏好，不能偷偷把所有其他会话原文塞进来。

切换会话不抢占另一端的语音播放。用户选择“在这里继续语音”时才转移声音焦点。旧设备接到焦点撤销事件并停止播放。

## 4. 场景 B：手机发起 Mac 任务

用户说“把 Mac 下载目录里的论文整理到项目文件夹”。聊天展示解释后的目标设备、主要操作和任务卡片。路径存在歧义时，用一条具体问题补齐；已有明确规则和授权时直接执行允许的步骤。

Mac 离线时显示“等待 Mac 上线”，并允许取消或修改截止时间。Mac 上线后重新检查能力、授权和路径；失效时显示具体原因。执行中显示有意义的阶段，例如“识别文件”“整理 8 个文件”“核对结果”。

完成后展示实际移动了什么、哪些未处理、可用的恢复信息。任务结束通知只在符合偏好的设备提醒一次，其他客户端仍同步任务状态。

## 5. 场景 C：记忆更正

用户说“以后 Mac 的工程目录改成另一个位置”。助理把来源记为当前设备，把适用范围记为 Mac，更新对应事实的版本，并在回复中简短确认适用范围。

记忆中心展示旧值、新值和来源。正在排队的任务在执行前重读相关记忆；已经开始执行的步骤不因为记忆改变而悄悄换路径，需要暂停或明确记录使用的旧快照。

## 6. 场景 D：自然语音与打断

点击或唤醒进入倾听状态；用户说完后，形象进入思考，再随首段音频开始说话。用户中途说话，旧音频立即停止，形象退回倾听。

“停一下”默认停止当前播报；“取消这个任务”才触发任务取消。语音打断与操作取消分开，避免用户只是插话却中止后台工作。

网络中断时显示连接状态，已经接受的任务继续在云端存在。不能因为语音连接关闭就把任务当失败；也不能在重连后自动重放已说过的整段音频。

## 7. 场景 E：主动联系

主动消息应能说明来源，例如“你让我在今晚提醒整理资料”或“Mac 上的任务已经完成”。非任务类关心由用户开启，按可配置节奏工作，不把情绪表达当成强迫用户回应的理由。

用户在 Mac 忙碌、手机锁屏时，可以只投递一条静默通知；没有可靠的在场信息时，不假装知道用户正在做什么。

## 8. 异常文案原则

| 系统状态 | 面向用户的表达 |
| --- | --- |
| 目标离线 | 等待 Mac 上线，任务已保存 |
| 缺少权限 | Mac 尚未允许屏幕操作，点此查看设置 |
| 结果不确定 | 操作可能已完成，正在核对，暂不重复执行 |
| 模型不可用 | 暂时无法继续分析，任务已保留，可以稍后重试 |
| 记忆索引滞后 | 直接读取最新事实，必要时说明部分历史检索暂不可用 |
| 设备被移除 | 任务暂停；重新选择设备不会自动继承原执行授权 |

验收时需要覆盖窄屏、大字号、键盘导航、字幕模式、无声音和无形象模式。
