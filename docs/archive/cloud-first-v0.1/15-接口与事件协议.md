# 接口与事件协议

> 历史方案：云端 Agent 架构，已于 2026-11-22 被边缘 Agent 架构替代。仅作历史参考，当前设计见 [产品文档](../../product/README.md)。
## 1. 协议归属

本文所有 `/v1/` 路径和 JSON 都是拟新增的产品协议，不是 OpenClaw 现有接口。Gateway 调用封装在内部适配器，客户端只依赖产品协议和受限节点连接。

REST 负责命令与快照读取，WebSocket 负责实时事件。音频使用独立媒体会话，不挤占领域事件流。部署默认使用 TLS，原生客户端将凭据放认证头或经验证的连接握手中，不拼入长期 URL。

## 2. HTTP 约定

所有写命令携带稳定 `Idempotency-Key`；同 key 和同 payload 返回同一结果，同 key 不同 payload 返回冲突。幂等键在 owner + 命令种类下唯一，保留窗口至少覆盖该操作允许的重试周期；任务步骤的幂等记录随任务生命周期保留。

涉及修改已有实体时携带 `expected_revision`，DELETE 可使用等价的 `If-Match` revision 条件；不匹配返回 `REVISION_CONFLICT`。请求 ID 用于追踪，不代替授权；owner 从认证结果确定。时间为 UTC ISO 8601，ID 均不透明。

`tasks/{id}/resolve` 的 action 限定为补参数、建立所需授权、请求重新核验和人工确认结果等枚举；每种 action 有独立 schema 与权限。人工确认明确标记来源，不伪装成设备证据。

## 4. 任务提交示例

```json
{
  "request_id": "req_demo_01",
  "conversation_id": "conv_demo_01",
  "goal": "整理 Mac 下载目录中的论文",
  "target_device_id": "device_mac_01",
  "parameters": {"workspace_ref": "workspace_papers"},
  "expected_device_revision": 12
}
```

来源设备由服务端身份决定。`workspace_ref` 由设备受控解析，不能让模型猜一个绝对路径就获得任意目录操作权。示例 ID 不代表已存在真实设备。

接受响应返回 task ID、当前 status、revision、目标和查询入口。HTTP 202 表示意图已持久接受，不等于执行完成。

## 5. 消息提交状态

`request_submissions.state` 使用 `queued`、`submitted`、`submission_unknown`、`responding`、`completed`、`failed`、`cancelled`。它与任务状态机独立。

产品 API 先持久保存请求，再通过内部 outbox 提交 Gateway。若提交连接中断且无法确认 Gateway 是否启动，进入 submission_unknown，按 request correlation 查询；不能自动重发一遍。Gateway 适配原型必须验证能否可靠查询关联运行，否则 UI 保留明确未知状态。

## 6. 领域事件封装

```json
{
  "schema_version": 1,
  "event_id": "evt_demo_01",
  "stream_seq": 241,
  "type": "task.updated",
  "occurred_at": "2026-11-21T15:00:00Z",
  "aggregate": {"type": "task", "id": "task_demo_01", "revision": 5},
  "correlation_id": "req_demo_01",
  "payload": {"status": "waiting_device", "target_device_id": "device_mac_01"}
}
```

owner 在服务端绑定的订阅范围内，不能由客户端随意切换。客户端按 event ID 去重、按 aggregate revision 忽略旧更新。订阅游标不透明，带主人与订阅范围约束，过期返回 `RESYNC_REQUIRED`。

## 7. 事件类型

持久事件包括 `device.changed`、`capabilities.changed`、`memory.changed`、`task.updated`、`step.updated`、`notification.updated`、`persona.changed` 和 `conversation.updated`。

临时流包括 `response.delta`、`response.final`、`voice.segment`、`avatar.state`。文本 token 和音频帧不要求永久补放；最终文本从 Gateway 读取。临时流携带 response ID、generation 与 response 内序号，不使用 domain stream_seq 假装可以永久重放。

## 8. 重连与补读

WebSocket 连接后订阅带 cursor；服务端校验权限、补读保留期内事件，再转实时。首次连接或 cursor 失效时先取 snapshot，随后订阅 watermark 之后的事件。快照与水位必须定义一致读取边界，不能先读水位、再随意拼各表结果。

客户端不把“WebSocket 已连接”显示成“所有数据同步完成”；补读完成有明确标记。

## 9. 错误码

| code | 客户端行为 |
| --- | --- |
| `AUTH_REQUIRED` / `BINDING_REVOKED` | 停止受限操作，重新认证或显示已移除 |
| `DEVICE_OFFLINE` / `DEVICE_NOT_READY` | 进入等待；不能改目标重试 |
| `PERMISSION_REQUIRED` | 展示具体所需授权 |
| `REVISION_CONFLICT` / `IDEMPOTENCY_CONFLICT` | 重读或修正，不能原样无限重试 |
| `OUTCOME_UNKNOWN` | 转对账，不自动重复写操作 |
| `PROVIDER_UNAVAILABLE` | 按预算退避；保留任务与请求身份 |
| `RESYNC_REQUIRED` | 丢弃过期游标并重取快照 |
| `PROTOCOL_UNSUPPORTED` | 保留只读 / 更新入口，不执行未知命令 |

响应包含 `retryable`、trace ID 和可展示原因；retryable 只代表允许在指定策略下重试，不表示任意副作用都可直接重放。

## 10. 版本与测试

新增可选字段保持向后兼容；改变字段含义或状态转换需要升级协议版本。设备能力握手声明支持的 schema 范围。将消息 / 任务幂等、事件补读、权限过滤和旧客户端兼容纳入契约测试。
