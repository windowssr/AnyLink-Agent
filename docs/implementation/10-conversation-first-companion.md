# V0.6：对话驱动的桌面伙伴与启动出场

Mac 桌面版本 0.6.0；云端服务继续使用 0.3.0。核心交互是“用户对话输入 → 本机 Agent 理解 → 调用桌宠工具 → 原生应用执行 → 回执与语音回复”。桌宠自身不再显示对话气泡、文字卡片或右键设置菜单。完整对话、工具记录和故障信息仍可在主聊天窗口查看。

## 默认行为与用户入口

主动招呼、自由行走、中文语音播报均为标准配置。首次升级到 V0.6 会一次性将三项设为开启，清除旧菜单的免打扰与隐藏状态；之后尊重用户通过对话设置的偏好，不在每次启动时覆盖。声音沿用用户已同意的“活泼甜妹”微软在线神经女声，文本与语音处理边界见 V0.5 文档。

点击大肥鱼打开主助理聊天，拖动仍可移动形象。主聊天拥有本机桌宠管理工具，用户无需选择工具或填写参数，例如：

- “变小一点，回到右下角。”
- “安静一小时，之后继续陪我。”
- “恢复正常，别关掉主动聊天。”
- “走两步，开心一点。”
- “先躲起来；出来吧。”

模型按意图选择工具，应用不增加另一套关键词匹配命令。夜间 23:00–08:00、离开超过五分钟、睡眠、任务忙碌、用户免打扰和系统减少动态效果等运行约束仍由本机执行。开启主动陪伴不意味着持续发声、持续走动或绕过这些约束。应用菜单保留基本窗口、权限入口与紧急停声；桌宠不提供设置界面。

## 模型工具与本机控制

`anylink_companion_expression` 继续负责白名单表情和动作。新增 `anylink_companion_control`，支持：

- `status`：读取当前显隐、大小、主动招呼、漫游、语音、安静时限和运行状态。
- `configure`：显式设置 `roaming`、`proactive`、`read_aloud`，不使用容易重复翻转的 toggle。
- `quiet`：安静 0–720 分钟，0 表示恢复；到期由本机时钟恢复。
- `walk`、`pet`：安排一次散步或摸头动作；回答内容仍由模型生成。
- `resize`：0.8 / 1 / 1.25 倍，保持人物比例。
- `reset_position`、`reload`、`show`、`hide`：位置、形象重载与显隐。
- `open_chat`、`open_voice`、`stop_speaking`、`chat_now`：打开交互、停声或提出一次招呼请求。打开语音面板不会自动开启麦克风。
- `credits`：打开固定的角色来源页面，不接受任意外部 URL。

普通主 Agent 可管理上述自身桌宠表现；主动陪伴 Agent 只允许表情、`status` 和 `walk`，不能自行重新开启主人关闭的设置、解除免打扰或执行其他软件任务。插件、前置工具 hook 和本机参数校验共同限制范围。其他频道不能调用此本机通路。

散步在当前模型任务、声音合成与播放结束后执行。`queued` 只表示已安排；受系统减少动态效果、睡眠、隐藏等条件限制时返回未执行。模型不得把排队或未知结果说成完成。普通聊天直接生成回答，不为每次回答再建立一个主动招呼回合。

```text
用户输入 → Mac OpenClaw main → anylink_companion_control
                                 ↓ 私有本机请求／回执
                          CompanionControlServer
                                 ↓
                          原生桌宠协调器
                       位置／大小／偏好／播放
                                 ↓
                 工具回执 → 同一模型回合 → 语音回复
```

控制桥位于 `data/mac/companion/control`，不开放新网络监听端口。原生应用签发进程 epoch 和 45 秒租约；请求带 epoch、工具调用的稳定摘要 ID、创建时间和 12 秒有效期。请求及回执采用 0600 权限、目录 0700。原生程序每 200 毫秒处理已发布的请求，执行后保存回执，重复 ID 读取既有结果；旧进程 epoch、过期、越界或睡眠状态的命令不会执行。

模型端最多等待十秒。没有回执则返回 `result_unknown`，不自动再次发起；应查询当前状态后再决定。隐藏只停止形象和聊天投影，控制桥继续运行，保证用户可通过对话把角色叫回来；退出应用则撤销控制租约。应用重启不重放旧请求。回执只保存动作结果及状态，没有聊天正文、录音、截图或令牌。

## 原生启动动画

启动直接复用现有 Live2D 模型与本机资源服务器，不新增模型、外部视频或新的模型 API 调用。等待模型加载完成后，在当前屏幕中央显示约 3.2 秒的出场过程：蓝色光门展开，角色淡入并向前出现，光门收起，人物窗口平滑缩放并移至已保存的桌面位置，最后抬手致意。首次默认右下角。

`CompanionEntrance` 在本机计算 appearance、portal、frame 三条状态。`CompanionView` 只展示模型，不绘制文字；渲染器仅接收这些数值及原有表情、嘴型和漫游参数，不接收聊天正文。窗口飞行时不拦截鼠标；落位后只在角色不透明像素上接收点击和拖动，其余区域穿透。

系统启用减少动态效果时，直接在目标位置短暂淡入，不使用光门或跨屏幕运动。动画每次应用启动执行一次，隐藏后叫回、重载形象、唤醒或普通点击不会反复播放。动画不触发录音，启动不强制弹出聊天；点击角色或 Dock 可打开聊天。

## 构建与回退

```bash
npm run desktop:companion:configure
node mac/cli.mjs config validate
npm run test:companion
npm run desktop:build
# 退出旧 AnyLink 窗口程序后安装；后台任务保持运行
npm run desktop:install
```

更新工具注册代码后，需要在本机 Gateway 空闲时正常重启该独立服务，使插件和人设重新加载；不要强行杀死有任务的 Gateway。只更新 Mac 端，不部署服务器或迁移数据库。真实密钥、租约、控制请求与回执、人物模型和运行日志继续排除在 Git 与源码发布包之外。

回退可恢复安装器保留的上一版 `.app` 及对应 Git 版本的本机插件／配置。旧应用不会刷新新控制租约，模型调用新工具时会得到桌面不可用，不把请求落到操作系统命令。保留工作区、模型、聊天和云端记忆，无需删除持久数据。

## 验收记录（2026-11-22）

- TypeScript 检查与 7 项 Node 伙伴测试通过；本机 Swift 行为测试覆盖启动进度、落位终点、负坐标与减少动态效果。原生控制测试拒绝过期、旧 epoch、重复、越界和睡眠请求，并检查私有权限。
- 真实主 Agent 模型回合产生 7 份原生回执，完成状态查询、小号、标准号、回右下角、安静、恢复及三项标准行为开启，约 20.9 秒。曾发现“标准大小”被理解成操作前尺寸，已在工具参数和人设中明确 0.8／1／1.25 映射后通过复验。
- 启动轨迹采样记录 `loading → emerging → settling → finished`，观察到 19 个不同窗口矩形。GUI 截图确认正常比例人物可见、没有气泡；右键前后界面无变化，不再出现菜单。
- 真实应用控制通路验证隐藏、隐藏期间读取状态、重新显示和排队散步；散步观察到 3 个不同横坐标，显示后未重播出场动画。测试结束恢复显示及三项默认开启。
- 验收不操作其他软件、不写长期记忆、不开启麦克风，无云端发布或数据库迁移。原始模型日志、运行凭据及测试产物不提交 Git。

本机证据位于被忽略的 `artifacts/companion-v0.6-entrance.json`、`artifacts/companion-v0.6-model-acceptance.json`、`artifacts/companion-v0.6-lifecycle.json`。真实模型验收源码为 `mac/tests/CompanionControlModelAcceptance.swift`，需已打开窗口应用、Gateway 完成启动并具备既有模型服务连接。
