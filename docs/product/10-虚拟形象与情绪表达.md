# 虚拟形象与设备中的生活感

修订：2026-11-22。本轮依据主人“像贾维斯或动漫中的伙伴，仿佛原生住在设备里”的反馈修订体验目标。下述为产品设计基线，不能视为新交互已实现；当前桌宠、原生聊天窗口和 Android 预览仍沿用已发布版本。

## 产品定位

AnyLink 的体验中心是住在设备里的大肥鱼：用户面对同一个角色，向她交代事情，看见她回应和行动，在需要时取得结果。聊天记录、任务列表和诊断界面是辅助入口。

保留已经选定的正常比例蓝色大肥鱼、可爱活泼的表达方向与设备本地 Agent。参考贾维斯的是随时可唤起、参与设备工作的存在方式；动漫式陪伴体现在动作、注意力和稳定的人格，不要求更换人物或叠加科幻仪表盘。

用户已明确的约束继续有效：不恢复桌宠对话气泡，不恢复右键设置弹窗，主动交流、自由活动和语音播报作为默认能力；通过自然对话调整偏好。语音输入仍按此前决定后续验收，本次设计不自行开启持续麦克风或添加唤醒监听。

## 日常存在

角色有安静、注意用户、倾听、思考、执行、等待、说话、休息等连续状态。当前任务、最近交互、用户是否离开、设备是否锁屏和用户的安静偏好共同决定表现，不能只靠固定间隔随机走动和重复问候营造陪伴。

她可以在不遮挡工作的屏幕边缘停留，在空闲时伸展、整理头发或短距离移动；用户呼唤或点击时转向用户，做事时收敛动作。选择停留位置应尊重当前显示器边界、输入区域、窗口交互和拖动习惯，不能突然挡住点击目标或抢焦点。

“有生活感”也包括不做动作的时机：用户专注、全屏演示、会议、连续未回应、免打扰或离开后，角色减少打扰。主动交流围绕有依据的任务变化和最近话题，不编造“刚刚看见你在做什么”。

## 交互从角色展开

Mac 的常用入口改为角色身边的轻量输入和结果层。单击或快捷键唤起一行输入，输入后收起，执行中保持可识别状态。语音接通后使用相同入口和响应所有权。完整聊天窗口保留为查看历史、长文和故障详情的二级入口，单击角色不应默认跳入管理控制台。

没有文字对话气泡。语音负责自然交流；文件列表、真实进度、待选择项和需要确认的动作可以用临时结果面板呈现。面板展示可操作的信息，使用后收起，不在人物周围不断堆积逐字聊天。

本地注意力反馈先于网络回复：用户叫她时可以立即抬头、转向或停止旧动作，不能等模型生成完毕才突然开始表现。后续语音、口型、表情和任务反馈围绕同一次响应协调，不各自播放一套状态。

## 用动作表达正在发生的事

执行文件搜索时，她可以转向工作区域，留在不会妨碍操作的位置；结果到达后看向结果面板，并简短提示找到的数量。访问受限时进入等待或说明状态；任务失败时不得播放成功庆祝动作。

情绪来自有依据的对话与任务结果，不要求每句话都做一个大动作。短反馈可以由本地状态机决定，复杂表达由 Agent 建议，本地映射器限制到已有动作并处理冲突。情绪不能改写事实、权限和实际执行结果。

人物不能靠屏幕位置“演戏”冒充执行：文件名和进度必须来自真实回执，“正在看”“找到了”“已完成”必须有对应证据。角色可以安慰用户，但不能假装知晓尚未获取的信息。

## 电脑和手机上是同一个她

用户不选择“办事大肥鱼”和“陪伴大肥鱼”。后台主动触发可以保留较窄的权限，但它使用统一的角色设定、用户偏好和当前事情的线索，不能成为另一个会话人格。

设备切换需要补齐短期连续性：当前事情、最近一句关键交互、来自哪台设备的任务、是否仍在执行、用户是否已听过结果。统一长期记忆目前已经实现，不能把它当作这部分短期连续性也已实现。

默认由最近接收用户输入的设备拥有本次对外回复。另一台设备执行任务后把证据交回该响应所有者，不默认两端同时播报。比如用户在手机说“帮我找电脑上的文件”，Mac 执行，手机里的她带回结果；电脑里的形象可安静展示工作状态。

跨端连续性以带来源和版本的任务摘要 / 交互摘要存储并交换，不引入云端 Agent 主进程；各设备仍拥有本地执行和系统权限。服务器可作为这些记忆或摘要的存储处，不能据此开始规划或执行设备任务。

## 感知范围与系统约束

优先使用已有本地任务、操作回执、前后台和锁屏等明确事件。感知其他应用、屏幕或声音要按具体用途和已有授权接入，不因为用户希望她“住在设备里”就推定已经允许持续截屏、后台录音或读取所有软件。

离线仍可保持本地形象和交互反馈，但需要模型或其他设备时明确说明连接状态。Android 的 App 内角色、系统悬浮层、前台服务、锁屏和进程回收分别设计与验收，不能承诺跨越系统限制无限常驻。

## 工程组织与下一步

本地驻留服务维护角色状态、当前响应所有者、任务和可用输入输出；表现层订阅这些状态，渲染和动画不自行调用模型。对话、工具执行、语音和动画共享 response ID / generation，打断后迟到数据不能恢复旧声音或旧动作。隐藏角色与停止任务分别处理，不能仅因收起界面就意外终止已接受的工作。

第一项体验施工优先放在 Mac：点击人物唤起轻量输入 → 使用现有主 Agent 执行 → 在人物旁边展示真实只读文件搜索结果 → 收起回到陪伴。先用已经打通的能力验证生活感，避免同时重做工具链、人物模型和语音提供商。

之后统一主动交流的上下文与响应所有权，再补状态驱动的环境行为、语音打断与跨端短期连续性。Android 先形成同一个角色的 App 内空间，系统悬浮形象另行实施。

验收关注完整体验：不打开完整聊天页也能交代一件小事；输入后人物立即作出本地回应；能看出她在听、思考、执行或等待；结果有真实证据；安静偏好生效；切换设备不出现两个角色抢话或无依据接话。

## 当前实现与素材

Mac V0.6 已有无气泡、无右键菜单的 Live2D 角色、启动出场、表情动作、规则驱动漫游、主动招呼和中文播报；当前点击入口、主动会话与状态协调尚未达到本页新目标。Android 已有 App 内形象、单一聊天入口和接入真实 Mac 的只读搜索，但没有系统悬浮、已验收的语音和跨端短期连续性。
