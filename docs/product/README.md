# AnyLink：边缘 Agent 产品设计

版本：Mac 桌面 v0.6／云端服务 v0.3／Android v0.1 工程，沿用边缘 Agent 架构。修订日期：2026-11-22。**Mac 本地 OpenClaw、云端模型与记忆、鼠标键盘工具已打通；蓝色大肥鱼已加入聊天表情动作、主动招呼、漫游和中文语音。** 当前实现采用无气泡、无右键菜单的对话驱动桌宠，包含启动出场动画，见[对话驱动伙伴](../implementation/10-conversation-first-companion.md)和 [Mac 电脑控制](../implementation/07-mac-computer-control.md)，基础记忆通路见 [V0.2 验收](../implementation/05-edge-validation.md)。Android 已新增 HBuilderX 工程、本地 Pi Agent 和电脑预览，并通过真实模型与统一记忆联调，见 [Android 施工记录](../implementation/12-android-foundation.md)；真机与设备间协作仍待后续验收。旧 V0.1 云端 Agent 原型已退役，历史数据保留。

用户始终与所在设备的 Agent 交互。Mac 运行成熟 harness，管理会话、上下文、工具循环、任务、权限、语音和形象；服务器只提供共享记忆与模型调用服务，以及这两种服务必需的身份、配额和运维设施。

Mac Agent 将模型请求发送给自己的服务器，服务器再调用 DeepSeek。模型计算仍在提供商，本机持有 Agent 控制权。共享记忆不意味着共享一个云端 Agent 进程，也不意味着每台设备各自维护冲突的长期事实。

此前把 OpenClaw Agent、交互入口和任务调度集中在云端的设计已归档为 [历史方案](../archive/cloud-first-v0.1/README.md)。它与当前用户要求不符，不能继续作为 Mac 接入施工依据。历史发布 tag 与验收证据不改写。

## 不再混淆的三个概念

模型 API 是推理服务；harness 是拥有会话与工具循环的运行时；记忆服务是长期事实的权威存储。前者经服务器统一调用，第二个在设备，第三个在服务器。

服务器会接触推理请求中的上下文，这是模型转发必然经过的数据；默认不因此持久保存全部聊天，也不接管本地 Agent。其他设备从记忆服务读取共享事实，不默认获取另一设备全部原始会话。
