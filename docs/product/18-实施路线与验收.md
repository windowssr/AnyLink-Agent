# 施工顺序与验收

## 0. 校正基线

停止云端派发固定动作执行器的方向，保留未提交原型的本地归档。明确已部署 V0.1 与目标不同；保留既有记忆和历史证据，不改写旧发布 tag。

## 1. 模型代理

在 ywc 增加标准模型 API，设备认证后直连 DeepSeek，验证 SSE、工具 schema、`tool_calls`、工具结果及错误 / 取消透传。不能通过云端 OpenClaw Agent 冒充模型转发。

## 2. Mac 成熟 harness

准备兼容的原生运行环境，隔离安装 OpenClaw profile。先使官方本地 UI / CLI 能通过自有服务器调用模型，再验证原生本机工具多轮循环。AnyLink 不重写 loop。

## 3. 云端记忆

本地 memory 插件接现有事实库，验证 global 与 Mac 事实、新会话召回、更正 revision、删除失效、来源绑定。关闭冲突的第二份长期记忆写入。

## 4. 本地任务与恢复

使用实际原生文件工具完成可核验任务，保存本地 run / 工具证据。练习代理断线、进程重启和结果未知；恢复查原运行，不能重开任务来掩盖不确定性。

## 5. 切换入口

日常交互转为 Mac 本地入口，停用旧云端交互 Agent。云端保留模型 / 记忆服务和历史只读管理。完成后记录源码提交、包版本、配置与实机结果，再发布新版本。

## 必须证明

- 用户输入提交到 Mac Agent，服务器没有另一份对话运行或工具循环。
- 服务端只见模型与记忆请求，文件操作确实发生在 Mac。
- 停止旧云端 OpenClaw 后，本机闭环仍成立。
- DeepSeek Key 仅在服务器，设备只持有服务凭据。
- 已更正 / 删除事实不会被旧缓存复活；结果不明时不自动重复副作用。

Android、语音、形象与跨设备任务在此后各自验收，不计入 Mac 基础闭环的已实现能力。
