# 部署运维与数据控制

## 目标部署

Mac：成熟 OpenClaw runtime、本地 UI、会话与运行状态、记忆适配插件、本机工具与权限。`ywc`：记忆 API、模型 API 代理、独立 PostgreSQL，以及认证、配额、审计与备份。

目标云端不需要为用户对话常驻 OpenClaw Agent，不需要云端设备步骤调度器。旧服务要在本机闭环验收后停用；当前 V0.1 暂保留为历史原型，不在文档修订时直接删除状态和数据库。

## 网络

开发阶段 Mac 经 SSH 隧道访问服务器 memory / model API，本地 UI 连接本机 Gateway。生产稳定连接方式后续单独配置；不把本机 Gateway 管理端口暴露公网。

服务器模型代理只准访问配置的提供商和模型，不提供任意 URL 转发。凭据按设备分配并可撤销，日志不记录完整请求正文和密钥。

## 两类备份

云端备份记忆、修订、索引源、撤销与配置；本机备份 harness 状态和必要执行证据。两者分别拥有恢复权威。恢复云端数据不能触发本机重放旧任务。

## 升级

分别升级 Mac harness / 插件与云端 API，保持协议兼容。先跑真实模型、memory CRUD 与本地工具闭环，再切换日常入口。旧云端会话和待办默认只读归档，不转换为自动执行指令。

## 资源

停止旧云端 OpenClaw Agent 后的服务器资源需重新实测，不继续把 V0.1 Gateway 的 1.5 GiB 限额作为目标服务要求。本机 Node 与 harness 兼容环境单独记录。
