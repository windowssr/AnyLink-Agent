# OpenClaw 在边缘设备上的集成

## 位置先固定

OpenClaw 的 Gateway、agent loop、session 和本机 tools 在 Mac。服务器不再运行对用户提供交互的 OpenClaw Agent。第一阶段选用成熟运行时并写窄适配层，不 fork 一套 Agent 主循环。

## 官方已提供的接缝

官方 CLI 文档说明 `agent --local` / `agent exec` 可在本机运行 embedded agent；常驻 Gateway 则持有自己的运行和会话。自定义 provider 支持 `baseUrl` 与 `api: openai-completions`，因此可把推理发送到自有模型 API。插件接口可以注册工具。资料见 [证据](20-参考资料与证据.md)。

这些是上游接口能力，不等于本产品的 Mac 接入已验证。实现时需在固定版本上验证实际配置、插件、工具调用与错误恢复。

## 三个适配点

1. **模型 provider**：指向 ywc 的模型代理，使用设备服务凭据；DeepSeek Key 不离开服务器。代理直连模型，不嵌套云端 OpenClaw Agent。
2. **memory 插件 / hooks**：本地取得 global 与设备事实，注入本地 prompt；明确记住 / 更正 / 遗忘时调用云端记忆 API。关闭并行的另一套长期事实自动写入。
3. **本地产品桥接**：将 UI、任务结果、语音与形象关联到原生 run / tool call。不负责云端领取任务或自研本机推理循环。

## 原生工具

沿用文件、进程、浏览器和系统能力的原生政策与权限。每类操作逐项验收。执行证据不足时如实保留待核对，不因成熟框架之名承诺所有动作都具备可靠回执。

## 配置与版本

独立 profile / 状态目录 / 工作区 / 回环端口；保留原生 session，插件通过正式扩展点接入。优先不改核心；若需要补丁，记录上游版本与原因。

固定 `2026.11.6` 的 npm engines 已查到需要 Node `>=24.16.0 <25 || >=26.1.0`，Mac 运行环境需单独准备。官方当前文档可能早于或晚于固定包，安装后的真实接口与测试才是兼容性证据。
