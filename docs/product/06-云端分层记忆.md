# 云端分层记忆

## 权威与运行位置

服务器保存长期事实、修订、来源、删除状态和索引。边缘 Agent 通过工具读取 / 写入这些事实，在本机组装上下文。服务器不为这些请求启动一个对话 Agent。

原始会话与执行日志默认属于对应设备。需要共享的摘要可以显式写为记忆；不能把全部聊天自动当成长期事实。

## 层级

- `global`：人格设置、共同偏好、长期目标及稳定背景。
- `device`：设备目录、应用环境、操作习惯，带 `applicable_device_id`。
- 全局设备目录：保存设备标识和事实引用 / revision，指向设备事实的当前有效版本。

目录是索引，不是另一份可独立修改的事实。首版直接由 PostgreSQL 当前事实生成，避免摘要滞后覆盖真实内容；全文 / 向量增强以后再加。

## 来源与适用性

`source_device_id` 来自设备认证；`applicable_device_id` 来自事实适用范围；`source_ref` 指向本地消息或结果引用。源消息可能只存本地，云端保留引用不代表可直接读取全文。

用户在手机声明 Mac 目录：来源是手机，适用设备是 Mac。设备重装和绑定变化后复核环境事实，不默认旧权限仍有效。

## 显式写入

初期仅在用户明确要求记住时同步保存。Mac memory 插件提交内容、scope、来源引用及稳定幂等键；服务器验证并事务保存；本地收到成功后才确认已记住。服务器不自行抽取全部聊天。

后续的候选提取若启用，由边缘 Agent 提出，候选、用户陈述和设备观测保持证据类型，不能把模型推断直接升级为事实。

## 对话中的学习（体验目标，尚未启用）

当前实现会利用当前会话，并在主人明确要求时保存长期事实；没有全量历史自动提取、持续训练模型权重或自动积累可执行技能。统一事实共享已通过验收，不意味着已经实现了自学习。

目标是让大肥鱼逐渐掌握主人的偏好和已验证的做事经验：

- 明确的偏好：用户说“以后结果先给我看路径”，在对话学习范围已开启后形成有来源的偏好；“这次只说一句”保持为本轮约束。
- 事情的连续性：保存当前事情的简短摘要、发起设备、目标设备和真实状态，支持“刚才那份文件”之类的接续；不把所有逐字聊天复制成永久事实。
- 成功的做法：从可核验的任务回执总结适用条件和方法，例如某类项目资料通常先查哪个已开放目录。经验是下一次决策的参考，仍受当时工具、目录和系统权限约束。

候选提取和总结由当前设备 Agent 执行，云端提供带来源、版本和作用域的存储与检索。模型推理所得的“我猜你可能喜欢”保持为推测，附置信度和失效时间；用户明确纠正时，当前陈述优先。失败记录不自动升级为成功经验。

设计上分别记录用户偏好、短期事情摘要和操作经验，附证据引用、适用设备、更新时间、状态和 revision；这是后续数据模型，不是当前事实接口已经接受的新字段。记忆内容不能自行授予工具权限、修改自身系统规则或安装执行代码。

学习范围通过对话控制，例如“以后可以帮我总结偏好”“这段不要记”“忘掉刚才那件事”“你为什么会这样认为”。默认从明确开启后的交互开始，整理旧历史是另一项有范围的操作。仅询问“她会不会学习”不改变现有记忆写入规则。密码和令牌不进入学习记忆。

这种学习更新的是记忆、偏好和经验，不代表远端 DeepSeek 模型的权重在设备上自动训练。角色表现可以因此更贴合用户，但不得声称因此获得了意识或没有依据的能力。

## 召回

本地 Agent 明确查询与涉及设备 → 云端按 owner 和 scope 筛选 → 返回当前有效正文、来源与 revision → 本地去重并裁剪预算。global 与适用设备事实组合由本地执行，不能仅按最后一次请求的设备缓存上下文。

统一索引能帮助另一设备发现某台设备的相关事实，但不会给予那台设备的系统权限。

## 更正与删除

修改带 `expected_revision`，冲突返回 409，不能静默覆盖。删除先标记墓碑，立即从当前检索和目录排除；本地下一轮刷新。旧会话仍可能包含旧文本，删除事实不等于擦除聊天、备份或已传给模型的内容。

离线缓存必须带 revision 和失效标记，不能把本地旧副本回写为最新事实。无服务时说明当前记忆覆盖不足；涉及关键路径的写操作不得静默使用无法验证的旧事实。

## 可复用实现

V0.1 的 PostgreSQL 事实表、修订、scope、CAS、软删除和动态目录可以复用。要改的是调用者：从云端聊天编排器改为设备 memory 插件，并补设备级认证。
