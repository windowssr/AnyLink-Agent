# 工具系统与本机操作

## 工具循环的位置

读取文件 → 调用模型 → 接收工具调用 → 操作本机 → 回传工具结果，这个循环全部由边缘 harness 控制。云端模型代理只搬运推理输入与输出，不运行这些工具。

## Mac

优先使用成熟 OpenClaw 的文件、进程、应用 / 浏览器等工具与原生权限机制。具体能力逐项验证后开放；先用可核验的文件场景打通，不自研只理解固定动作名称的替代 Agent。

文件工作区、命令权限和系统授权由本机配置。工作区是操作范围，服务器地址是模型服务地址，两者不能混淆。记忆里的路径是数据，不授予访问权。

V0.3 使用 `anylink-mac-control` 接入固定版本、官方签名的 Peekaboo 本机主机，提供软件 / 窗口列表、窗口图像和可访问性观察、点击、文字输入、快捷键、滚动与同窗口元素拖拽。控制由用户在 AnyLink.app 显式启用并完成系统授权。每次动作绑定本轮准确窗口观察，记录去重与未确认结果，工具返回实际新画面。截图经云端模型代理交给 Flash，不在云端执行输入。细节与真实验收范围见 [V0.3 施工记录](../implementation/07-mac-computer-control.md)。

## 记忆工具

本机工具可调用云端记忆 API，包括查询、保存、条件修订、删除及读取设备目录。长期事实只写同一云端权威库；本地会话日志与临时文件不冒充另一套长期记忆。

## 运行证据

工具输出关联本地 run / call ID。对于文件操作保留路径、结果与必要摘要；对于应用操作保留实际反馈。模型声称“完成”不能替代工具证据。

## Android

后续使用 Android 本地 harness 和系统能力适配。现有 companion / remote UI 是否只连接其他 Gateway 需核实，不能作为“本机完整 Agent 已实现”的证据。
