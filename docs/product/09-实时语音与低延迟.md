# 实时语音与低延迟

## 1. 目标和测量口径

语音目标是自然轮流、能打断、状态清楚。真正零延迟不作为承诺。核心指标是“用户有效话音结束到首段可听语音”的时间，不用首个文字 token 代替。

V1 暂定验收目标：在约定网络、设备、语言和固定测试集下，P50 不超过 1.5 秒，P95 不超过 3 秒；本地停止旧播放目标不超过 150 毫秒。以上是目标，需原型评估后确定发布门槛，当前没有实测支持。

网络延迟、端点判断、ASR、模型首段输出、TTS 首包、解码与缓冲都单独打点。不能把各组件的 P95 相加当成完整链路 P95。

## 2. 两条语音路径

### 首版：流式 ASR → agent → 流式 TTS

设备完成采集、回声处理、VAD 和播放；服务器接音频、调用 ASR，最终识别文本进入同一聊天会话；OpenClaw 生成文本或工具意图，服务器把可播报段送入 TTS，客户端流式播放。

优势是与文字路径共用人格、工具和记忆。DeepSeek Key 只解决其中的模型调用，ASR 与 TTS 还需另外选服务或自托管实现，属于待验证依赖。

### 后续：实时语音模型

语音模型可以直接处理音频，但必须接同一记忆快照和任务工具。每轮只能选一个响应所有者，不允许语音模型先答一套、文字 agent 再答另一套。

如果提供商无法及时更新记忆、无法可靠取消旧输出或不能接统一工具，则不进入正式实时路径。首版不强制采用 Grok 或其他特定提供商。

## 3. 音频会话

语音 session 保存主人、会话、当前设备、voice mode、persona revision、memory watermark、response owner、声音焦点租约和 generation。

声音焦点由服务端授予一个设备，第一版同一主人同一时刻只允许一个活跃语音焦点。焦点切换使旧租约失效，旧设备停止播放和继续上行；UI 可以在其他设备继续显示字幕。

音频格式、采样率、编码、分片长度由 transport capability 协商，不在业务 API 写死。初始原型采用成熟音频传输库支持的格式，避免未经验证的自定义编解码。

## 4. 流式输出

ASR interim 只用于字幕；只有最终转写或服务端明确提交的稳定片段进入正式用户消息。TTS 按语义短段切分，先生成可播报回应，再继续长答案。

涉及任务时可以先说“任务已保存，正在等待 Mac”，前提是任务已持久接受。不得为了显得快而先说“已经完成”。

每段音频带 response、segment、generation 和相对时间戳。字幕、口型和动作使用同一音频时间轴。迟到、重复和旧 generation 片段直接丢弃。

## 5. 打断与取消

检测到用户开始讲话，设备先本地静音旧播放，再通知服务端 cancel 当前响应 generation。服务端停止可取消的 TTS / 模型输出，记录本轮中断；已发生的计费或工具效果不能假定回滚。

默认打断只影响交流。任务继续运行，除非用户明确要求取消任务；后者进入任务状态机，不和关闭麦克风或页面混用。

## 6. 记忆同步

开始语音和每轮响应前检查 memory watermark。全局事实被更正或删除后，语音 session 标记上下文过期，下一轮刷新。实时提供商如果保留旧上下文且无法可靠更新，则重建 session。

语音转写进入正常会话后，再提取记忆候选。未稳定转写、被噪声误触发或用户尚未表达完的内容不直接存成长期事实。

## 7. 异常与降级

- ASR 不可用：保留文字入口，说明无法识别，不重复提交已有消息。
- TTS 不可用：展示文字和形象思考 / 空闲状态，不一直卡在说话动作。
- 语音连接断开：结束媒体会话；已持久接受的任务和聊天运行按各自状态恢复。
- 手机进入后台：按实际系统能力继续或停止采集，不能伪装仍在倾听。
- 回声或串音：降低播放 / 识别并发，提供按住说话模式。

## 8. 资源与隐私

默认不长期保存原始音频；需要诊断或用户收藏时单独开启并设置期限。文本转写遵循会话保留策略。客户端不持有长期模型或语音 provider Key；如未来需要直连媒体服务，只发受限、短期会话凭据。

## 9. 验收

中文长短句、口音、噪声、耳机 / 扬声器、跨设备抢焦点、连续打断、后台切换、重连、TTS 失败、记忆更正和工具任务去重都纳入测试。完整报告必须给出实际网络条件、样本数、P50 / P95 和失败率。
