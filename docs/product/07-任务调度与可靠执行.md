# 任务调度与可靠执行

## 1. 任务与步骤

任务描述用户想达到的结果；步骤描述一次可派发的、目标明确的操作。规划可以修改尚未执行的部分，但每个步骤的操作内容、目标绑定与幂等键在开始执行后不可变。

任务保存 `origin_device_id`、`target_device_id`、发起会话、当前计划 revision、期限、授权引用和结果。多设备任务显式拆成各自目标的步骤，不让“任意在线设备”隐式接单。

## 2. 任务状态

| 状态 | 含义 | 离开条件 |
| --- | --- | --- |
| `draft` | 尚未持久接受的候选计划 | 用户意图与目标足够明确后提交 |
| `waiting_input` | 缺少必要参数 | 补齐参数并重新校验 |
| `ready` | 可调度 | 有合格设备、能力与授权 |
| `waiting_device` | 设备离线或当前不能执行 | 目标设备恢复并通过就绪检查 |
| `waiting_permission` | 缺少当前需要的授权 | 有效授权建立或用户取消 |
| `running` | 有已派发或正在执行的步骤 | 步骤结果提交、等待或异常 |
| `cancel_requested` | 已请求停止后续工作 | 在途步骤停止并完成对账 |
| `needs_reconciliation` | 操作是否发生尚不明确 | 回执 / 后置条件 / 用户处理确认 |
| `succeeded` | 所有必要结果已验证 | 终态 |
| `failed` | 无法继续且没有未对账副作用 | 终态 |
| `cancelled` | 后续工作停止且在途结果已归档 | 终态；可能包含已完成部分 |
| `expired` | 期限前未能开始 / 继续且无在途不确定操作 | 终态 |

`draft` 可以只存在于规划视图；其他状态必须持久化。终态不会因为迟到模型文字改变。需要重做时创建新任务或明确的新计划，不偷偷重启旧终态。

## 3. 步骤状态

步骤使用 `queued -> leased -> accepted -> running -> succeeded / failed`。可能转入 `needs_reconciliation`、`cancelled` 或 `skipped`。

`accepted` 表示设备已经持久记录接收；不表示操作完成。`failed` 只适用于确认没有发生未知副作用，或失败结果本身已明确的情况。状态与当前 attempt、fencing token 一起条件更新。

## 4. 调度与租约

worker 从数据库认领 ready 工作，写入租约、attempt 和递增 fencing token。GUI 类步骤同时占用目标设备交互锁；文件类步骤可按目录资源锁控制并发。首版每台设备只运行一个 GUI 写任务。

租约到期说明调度者失去继续派发权，不代表设备已经停止动作。新 worker 不能立即在同一资源上开启第二个冲突动作；先对账旧 attempt。设备也校验 token 与本地资源锁，拒绝旧调度者的后续命令。

fencing token 不能撤销已经送入外部 App 的点击。对于已开始的未知动作，保留资源隔离和 needs_reconciliation，不能把“新 token 更大”当作可以安全重试的理由。

## 5. 执行授权

授权绑定主人、目标绑定、工具类别、操作边界、有效期和计划摘要。已有站立授权可覆盖低风险、范围明确的操作，不要求每一步都向用户弹窗；超出边界时才转 waiting_permission。

OpenClaw 一次运行的临时工具权威不能原封不动保存到任务表，等设备上线后再用。每次续跑基于当前任务授权重新建立受支持的运行上下文；撤销、配对变化和参数变化都重新校验。

## 6. 本地执行日志

设备执行器在动作前持久保存：task、step、plan revision、操作 hash、幂等键、绑定代次、attempt 和 token。相同幂等键且操作 hash 相同的重复请求返回已有记录；同一键对应不同操作则拒绝。

动作完成后保存结果、后置条件、时间和附件引用，再上传回执。设备必须能按 step / 幂等键查回执。UI 进程重启不清空此日志；旧日志按确认与保留策略回收。

本地日志与外部 App 无法普遍构成原子事务。设备在“动作发生后、回执写入前”崩溃仍可能产生未知结果，需要后置条件核验。

## 7. 重试分类

| 情况 | 处理 |
| --- | --- |
| 派发前发现离线 | 等设备，尚未执行 |
| 明确拒绝且保证未进入动作 | 修复条件后重试，记录新 attempt |
| 只读查询失败 | 在预算内重试，但保留错误证据 |
| 设备已 accepted 后断线 | 进入对账，不直接重放 |
| 执行完成、上传回执失败 | 设备重传同一回执，云端幂等接收 |
| 文件移动结果未知 | 检查源 / 目标和内容标识，确认后决定下一步 |
| 外部发送或提交结果未知 | 查询业务记录或交由用户处理，不盲目再次提交 |

## 8. 取消与期限

取消先阻止新步骤，通知设备尝试停止可中断工作。已经执行的操作保留结果，任务详情显示部分完成。存在未知操作时保持 needs_reconciliation，不能立刻显示“全部取消成功”。

期限到达时，未派发工作可以 expired；已经 accepted / running 的步骤先停止与对账，不能用过期状态掩盖未知副作用。

## 9. 结果判定与 Workboard

任务成功由必要步骤结果和后置条件计算，模型总结只是展示层。长任务可以有人工复核阶段，但不把“模型说完成”视为设备证据。

复用 Workboard 的任务卡片、会话关联和尝试视图；产品账本是设备任务权威。投影失败写入待重建事件，不能影响步骤提交；反过来，Workboard 的会话终态也不能直接覆盖物理设备步骤。

## 10. 验收

必须演练：派发前离线、接受后断线、成功回执丢失、worker 崩溃、设备崩溃、服务器重启、并发取消、租约到期旧 worker 复活、重复命令、绑定撤销和计划参数变更。验收目标是状态可解释且不盲目重复副作用，不承诺普遍 exactly-once。
