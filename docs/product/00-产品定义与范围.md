# 产品定义与范围

## 1. 产品目标

让用户在电脑和手机之间感受到同一个助理持续存在：它知道长期目标，能理解当前设备的环境，能够把明确授权的事情交给正确的设备处理，并在恰当的时机继续交流。

产品价值由三个闭环构成：交流后留下可靠记忆；提出任务后得到可核验结果；设备切换后上下文和任务仍连续。

## 2. 首批用户与默认环境

第一阶段只服务一个主人，允许该主人拥有多台设备。默认有一台长期在线的自管服务器、一台 Mac 和一部 Android。服务器地区、域名、硬件、语音提供商尚未确定。

一位主人拥有一个主要助理身份。可以有专门负责研究、编程等工作的内部工作角色，但它们的结果回到主人格；不把“每台设备一个独立人格”作为默认实现。

未来多人产品不在当前隔离承诺内。数据结构保留 `owner_id`，方便迁移；这不代表已经完成多人 SaaS 的权限隔离设计。

## 3. 产品能力

| 能力 | 用户看到的行为 | 系统必须做到 |
| --- | --- | --- |
| 统一身份 | 手机和电脑上是同一个助理 | 同一人格版本、统一记忆、明确的会话关系 |
| 长期记忆 | 新会话仍记得重要信息 | 结构化保存来源、作用域、版本和更正关系 |
| 设备理解 | 知道 Mac 项目路径，不套用到手机 | 来源设备、适用设备和执行设备分开 |
| 执行任务 | 手机上下指令，Mac 能处理文件 | 明确目标、执行授权、步骤账本、回执和恢复 |
| 虚拟形象 | 说话时有口型、动作和表情 | 同一输出驱动音频与动画，状态可以打断 |
| 语音 | 能自然轮流说话，也能中途打断 | 流式处理、声音焦点、取消旧音频和延迟监控 |
| 主动联系 | 到时提醒、任务完成后联系、适度关心 | 事件驱动、免打扰、频率限制和多端去重 |
| 可管理 | 能查看、纠正记忆和任务 | 管理页面、修订记录、删除与对账入口 |

## 4. 范围分层

### V0：验证架构

验证云端 Gateway、DeepSeek、多端身份、全局 / 设备记忆和一类可恢复任务。允许使用原生 OpenClaw 客户端配合开发调试界面，不把它视为最终产品体验。

### V1：个人可日常使用

提供统一客户端体验、记忆管理、任务中心、可打断语音、基本虚拟形象和任务完成通知。Mac 优先支持结构化文件 / 应用工具；Android 优先支持明确的系统能力。任意 App GUI 操作按已验收的能力逐步开放。

### V2：丰富伴随体验

增加更自然的实时语音、更多动作与表情、基于长期目标的主动交流，以及更复杂的跨设备任务。始终沿用同一份记忆和任务状态。

## 5. 第一版不承诺的能力

- 所有 Android 机型上无限后台运行、无限后台麦克风或锁屏后随意控制 App。
- 所有电脑 / 手机软件都能稳定自动化。
- 任意网络条件下的零延迟语音。
- 外部界面点击和提交具备普遍的 exactly-once 保证。
- 删掉一条长期记忆就等于同时删掉所有历史聊天、备份和模型已经见过的内容。

这些边界必须体现在具体能力和验收条件中，不能在用户操作时突然暴露。

## 6. 产品原则

1. 同一事实只有一个当前权威版本，索引和缓存可以重建。
2. 正在聊天、任务正在执行、任务已经完成，是三个不同状态。
3. 目标设备不能静默替换，离线设备上的任务明确等待。
4. 执行结果以设备证据和后置条件为准，模型文字不能直接宣布成功。
5. 人格表达影响语气、动作和互动节奏，不改变事实、权限或任务结果。
6. 用户可以检查记忆、修正误解、暂停主动联系、停止声音和取消尚未执行的步骤。

## 7. 成功标准

在新会话中跨设备召回全局事实；从手机成功发起并跟踪 Mac 任务；设备或服务器重启后任务状态仍可解释；更正设备事实后另一端使用新版本；同一语音响应只在一个设备播放；用户能理解助理为何主动联系。

量化指标和分阶段验收见 [实施路线与验收](18-实施路线与验收.md)。
